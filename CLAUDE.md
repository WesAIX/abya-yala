# abya-yala — конспект по истории коренных народов Америки

Текстово-графический конспект для самообразования. Владелец — не историк, у
него технический бэкграунд (Linux/BSD, сети, ИБ, Python, Go, системное
проектирование); историю изучает с уровня «вдумчивый любитель». Объяснять
механизмы и причины, не пересказывать учебник и не предполагать знания
историографии.

Язык — русский; английские термины — только устоявшиеся.

## Главное правило: не выдумывать

- Не выдумывать даты, цифры, цитаты, атрибуции и выходные данные изданий.
  Если нет уверенности — так и писать («не удалось проверить», «по одним
  данным… по другим…») или оставлять пометку в `todo`.
- Строго разделять **факт** (со сноской), **оценку** (с именем автора) и
  **гипотезу** (с явной пометкой). Разметка — в `chapters/README.md`.
- Тезисы проекта — рабочие. Если источник их уточняет или опровергает,
  писать это прямо, а не подгонять материал под тезис.
- Источники: первичные и академические в приоритете; популярные
  (`kind: popular`) — только как дополнение и никогда как единственная опора
  для факта.
- Запись в `sources/bibliography.json` получает `"checked": true`, только
  когда выходные данные сверены с самим изданием или каталогом. Записи,
  добавленные по памяти, остаются `false`.

## Данные

- Данные отдельно от отображения: `data/*.json` или `*.csv` со ссылками на
  источники; визуализация только читает их.
- У каждой цифры — поле `sources` (`{ref, loc, note}`), `ref` — ключ из
  `sources/bibliography.json`. Не ставить ссылку, если утверждение не
  проверено по этому источнику: пустой `sources` честнее.
- У каждой даты — `dating`: `documented` / `approx` / `conventional`. Всё
  до 1500 г. — не точнее `approx`.
- Где оценки расходятся — диапазон и автор каждой оценки, а не среднее.
- Для нового набора сначала пишется JSON Schema в `data/schema/`, затем
  запись в `DATASETS` в `tools/validate.py` (без неё валидатор считает набор
  ошибкой), затем данные.

## Визуализации

- Статический HTML + d3 с CDN (cdnjs, версия пинится), без сборки и без npm.
- Общие токены оформления — `visuals/shared/tokens.css`; цвета полос графа
  `--c-*` и цвета зон `--z-*` одинаковы во всех визуализациях. Светлая и
  тёмная темы. Новую категориальную палитру проверять валидатором навыка
  dataviz (`validate_palette.js`) для обеих тем, а не на глаз.
- Без ложной точности: этнические территории не рисуются чёткими полигонами;
  миграции — стрелками, зоны — размытыми областями; даты до 1500 г.
  показываются приблизительными.
- Подложка карт — `visuals/shared/americas-50m.geojson` (Natural Earth 1:50m,
  обрезка и упрощение — `tools/basemap.py`), никаких внешних тайлов. d3-geo
  ждёт внешние кольца полигонов по часовой стрелке — скрипт это учитывает.
- Пути к данным относительные (`../../data/…`): страница работает и локально
  (`uv run python -m http.server`), и на Pages.
- Реестр Ройса (визуализация 5): прежде чем что-то делать, найти готовые
  оцифрованные полигоны и проверить их лицензию; без этого не начинать.

## Тексты

- Связная проза о механизмах и причинах, явный вывод в конце главы; без
  воды и школьного пересказа.
- Самоназвание + устоявшееся русское название при первом упоминании в главе:
  «ленапе (делавары)».
- Сноски — `[^ключ]` с ключом из библиографии; валидатор проверяет, что ключ
  существует.
- Работа итеративная: одна глава или одна визуализация за раз. Не писать
  несколько глав заранее.

## Иллюстрации в главах — обязательны

Требование владельца: в главах **обязательно** используются графические
материалы, причём любые, которые помогают понять механизм. Это схемы,
диаграммы, графики, карты, таблицы, кадры и ссылки на интерактивные
визуализации сайта, репродукции первоисточников, фотографии. Их можно и
нужно готовить самостоятельно и вставлять в текст, не дожидаясь отдельной
просьбы. Глава без иллюстраций не считается черновиком — валидатор это
проверяет.

- **Свои рисунки** — SVG, генерируются `tools/figures.py`: функция на
  рисунок, две темы (светлая и тёмная) из `visuals/shared/tokens.css`, файлы
  `chapters/img/<NN>-<имя>-{light,dark}.svg`. В главу вставляются через
  `<picture>` с `prefers-color-scheme`, чтобы GitHub показывал версию под тему
  читателя. Числа для рисунка — из `data/` с источниками; если рисунок
  схематичен, это написано **на самом рисунке** («Схема: кривая условная»).
- **Чужие изображения** — только общественное достояние или открытые лицензии
  (CC0, CC BY, CC BY-SA). Файл кладётся в `chapters/img/`, источник
  записывается в `sources/bibliography.json` с полями `url` и `license`, а в
  подписи указываются автор, источник и лицензия. Не использовать
  изображения человеческих останков, погребений и священных предметов,
  даже если лицензия это разрешает.
- **Оформление.** У каждой иллюстрации — номер («Рис. N.M»), подпись с видом
  материала (*данные* / *схема* / *оценка*), осмысленный `alt`.
  Цветовые палитры проверяются валидатором навыка dataviz.
- **Интерактивные визуализации** сайта упоминаются в тексте ссылкой на
  `https://wesaix.github.io/abya-yala/…` рядом с тем местом, к которому они
  относятся.

## Команды

```sh
uv sync
uv run tools/validate.py          # схемы, ссылки, сноски, покрытие источниками
uv run tools/bibliography.py      # пересобрать sources/BIBLIOGRAPHY.md (не править его руками)
uv run tools/figures.py           # перерисовать рисунки глав chapters/img/*.svg
uv run ruff check . && uv run ruff format --check .
uv run python -m http.server      # просмотр на http://localhost:8000/
uv run --group basemap tools/basemap.py   # пересобрать подложку карт (нужна сеть)
```

Перед коммитом все проверки (ruff, validate, `bibliography.py --check`, `figures.py --check`) должны проходить — их же запускает CI
(`.github/workflows/pages.yml`), и при ошибке сайт не публикуется.

## Публикация

GitHub Pages через Actions: `index.html`, `visuals/`, `data/` и
`sources/bibliography.json` копируются в `_site` и публикуются. Главы
читаются на GitHub, а не на сайте. Ссылки из глав на визуализации ведут на
`https://wesaix.github.io/abya-yala/…`.
